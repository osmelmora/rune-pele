# Corpus parity report

`pele parity` is the scoreboard for the port. It renders every example in Pele's documentation corpus through Pele and through this port. It then reports per diagram type how many outputs are byte-identical, how many differ, and how many this port cannot render yet. It also leaves both SVGs on disk for inspection.

## Sub-features

- `parity-all` reports every corpus type and a total row.
- `parity-type` limits the run to one type with `--type`.
- `parity-files` writes each source, Pele's SVG, our SVG when there is one, and `report.json`.
- `parity-gate` exits 1 when any source this port renders differs from Pele.
- `parity-unknown-type` rejects a type with no corpus file.
- `parity-harvest` renders every source of a ported type that Pele's own tests hold, and this port's own cases, through both engines.

## How to get to it (user POV)

- `pele parity` from a terminal.
- `pele parity --type <type> --out <dir>` for one type into a chosen folder.

## Gotchas

- Without `--out` the files go to `out/parity/`, which every run overwrites. Proof belongs under `out/verify/<run-id>/`.
- `identical` requires byte-equal SVG and equal width and height. Same-looking SVG with a different attribute order is a difference.
- `pele errors` counts sources Pele itself rejects at 1.13.0. They are neither passes nor failures of this port.
- The corpus files are `-docs.json` only. `agentflow-reference.json` is not part of the count.
- The corpus has 2 pie sources. The claim that pie is ported rests on `parity-harvest`, which has 8,368.
- The flowchart harvest holds small charts: a `maxWidth` changes few of them. The random flowcharts carry the width attempts, the routes with wide turns and the fills under edges. A change to those needs the whole `flowchart_parity` run, not the harvest alone.
- The corpus has 24 usecase sources. The claim that usecase is ported rests on `usecase_parity` and `usecase_front`.
- A `json` node's error carries the message of V8's `JSON.parse`, so a change of the Node pin can change it. `usecase_front` shows that as `rejected differently` on its `syntax, json` inputs; `crates/pele-core/src/diagrams/usecase/json.rs` names the V8 source it follows.
- A message of a usecase error can hold half of a surrogate pair, where V8 quotes one character of an emoji. This port's message is a Rust string and shows U+FFFD there, and the `usecase_front` op of the oracle does the same to Pele's.
- After a change of the Pele pin, rerun `scripts/harvest-pie.mjs` and `scripts/harvest-flowchart.mjs`, and commit the new `harvest.json` files before reading `parity-harvest`.
- The cases with render options go through the oracle's `render_with` op. A new option needs a line in `render_with` of the type's test (`crates/pele-core/tests/pie_parity.rs` or `flowchart_parity.rs`), which fails on an option it does not map.
- A class style list cannot start with a hyphenated property such as `font-size`: Pele's grammar reads the hyphen as `MINUS` and rejects the line. The random class diagrams keep to lists Pele parses, so a style path reaches the renderer.
- `class_parity.rs` maps the `monospace` render option, which sets class members in the monospace font.
- Agentflow has no `---` link: two or more dashes with no arrowhead open an edge label, which swallows the lines after it. A shape named in metadata has to be lowercase, so no source can name `collapsedGroup`. The random agentflows of `agentflow_parity.rs` keep to what Pele renders.
- Agentflow is the one type parsed with its `%%` comment lines kept (`DiagramKind::keeps_comments`), because its model holds the line and column of each statement. A change to preprocessing or to `Origin::locate` needs `agentflow_front` as well as the other front-end tests.
- `tests/fixtures/agentflow/harvest.json` also holds `reference`, the sources of `agentflow-reference.json`. They are extra inputs and no part of the 522.
- A `;` ends a sequence statement wherever it stands, so text such as `&amp;` splits its line in two. An entity code such as `#35;` is hidden before the parser reads the line and does not. The random sequence diagrams of `sequence_parity.rs` keep to text without a `;`.
- A sequence participant's `links` and `properties` take JSON. This port reads JSON nested up to 512 deep, so deeper JSON there is a limit error (`Diagram is nested too deeply.`) where Pele parses it. `sequence_front`'s `json_past_the_nesting_limit_is_a_limit_error` holds that.
- `sequence_parity.rs` maps the `monospace` render option, which sets a sequence diagram's messages in the monospace font.
- A wardley map is drawn twice for each plot width: once into a scratch Scene to find how far it reaches past the plot, then inside the group that frames it. Pele grows its bounds while it writes, and only then writes the title and the frame's translation, which come first.
- An XY chart's `Math.log10` is V8's fdlibm algorithm, ported in `diagrams/xychart/ticks.rs` beside the rest of the ticks, not in `js.rs`. Node's build on darwin arm64 still rounds about one result in 25,000 an ulp apart from this port. The tick step reads only the whole part, which `xychart_ticks` holds equal for every input, including each double within three of every power of ten. A Node pin change can move those ulps.
- `harvest-xychart.mjs` takes the text of the XY chart grammar's broken markdown rule from Pele's lexer (`BROKEN_RULE`). Pele's parser test reads it back from the lexer Jison generates, and Jison is not installed here.
- Each type's oracle ops live in `harness/<type>.ts`. The bundle's stamp hashes every `harness/*.ts` in name order, so the doctor fails after a change to any of them until `mise run setup` rebuilds it.
- Gantt reads the time. A parity draw pins `LayoutOptions::now` to Pele's corpus clock, 2026-01-15T12:00:00Z, and the oracle runs Node with `TZ=UTC`, so local time is UTC on both sides. A render option `now` reaches both engines through `render_with`.
- Gantt's dates are JavaScript's `Date` as V8 runs it (`diagrams/gantt/date.rs`, including V8's legacy date string parser). A change of the Node pin can change V8's parser: rerun `gantt_dates` after any Node bump.
- A gantt chart with a long task and excluded days schedules one day at a time, eleven passes over, against Pele's work limit. Its tests run in debug in about a minute each; a slow run points at a new heavy random input.
- Railroad's title, `accTitle` and `accDescr` tokens take no leading blanks, unlike the common ones in `diagrams/tokens.rs`, so `diagrams/railroad/lexer.rs` has its own. An EBNF `?` postfix pairs with any later `?` that has no `?` or `;` between them into a special sequence, as in Mermaid, so many random EBNF grammars are rejected by Pele and by this port alike.
- `scripts/harvest-railroad.mjs` runs Pele's own generators (`tests/support/railroad-oracle.ts`) through the harness's esbuild, with the reference parser stubbed out, so it needs `mise run setup` first.
- Architecture draws Mermaid's five built-in icons (`database`, `server`, `disk`, `internet`, `cloud`) itself when no host draws icons. The glyph table is `scene/glyph.rs`, and the walk reports it as `Geometry::Icon::glyph`.
- A cynefin diagram's boundaries are seeded from the config's `seed`, or else from the `idPrefix`, so the same source draws other waves under another prefix.
- The run makes one `node` call for the whole corpus. It takes a few seconds, so a long stall points at the oracle.
